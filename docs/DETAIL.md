# YAPI 连接器

把 DeepSeek Harness 对接到你们的 YAPI 文档服务。配置服务地址和凭据后，可以在对话里选择项目，并用 `/yapi-doc` 技能让 agent 基于你的口述生成接口定义、经**审查卡片批准**后写回 YAPI。

## 配置

配置入口在 **设置（Settings）→ 插件（Plugins）** 里，标签为 **「YAPI 连接器」**，这是最直接的入口。同一份配置表单也保留在 **插件（Plugins）** 页面：找到 **dsh-yapi** 包，点开 **「YAPI 连接器」** 这一行，再点 **“配置 / Configure”**。两处编辑的是同一份配置，改哪边都生效（均为即时生效，无需重启）：

- **Base URL**（必填）：你的 YAPI 服务地址，例如 `https://yapi.example.com`。**没有默认值，必须自己填写**；留空时所有 YAPI 操作会提示"服务地址未配置"。仅允许 https（本机 loopback 可用 http）。
- **Allowed hosts**（可选）：额外的主机白名单。留空表示不额外限制——所有请求 URL 都只由你填写的 Base URL 构造，不接受工具参数覆盖，因此不会有 SSRF 面；如需再收紧可填入允许的主机名。
- **项目列表（Projects）**：可配置**一个或多个** YAPI 项目，每个项目三项：
  - **id**：一个稳定的本地标识（如 `test`、`prod`），用于选择和切换；留空会自动生成 `p1`、`p2`…
  - **显示名**（可选）：友好名称；留空则使用从 YAPI 实时拉取的项目名。
  - **token**：该项目的项目级 token，可填 DSH 凭据**引用名**（全大写下划线，如 `YAPI_PROJECT_TOKEN`）或**直接粘贴明文值**。
- **Username / Password**（可选，全局）：YAPI 账号，用于登录获取会话 cookie；同样支持引用名或明文。仅当写入需要登录态时才需要。
- **默认项目 token（legacy）**：旧版单项目字段，仅当「项目列表」为空时作为唯一项目使用。新配置请用上面的项目列表。
- **写入前需要在审查卡片中批准**：开启（默认）时，生成的接口以审查卡片呈现，经你批准才会写入；关闭后计划自动批准并立即写入。

凭据既可填 DSH 凭据**引用名**（全大写下划线），也可**直接粘贴明文值**。明文只保存在本插件配置里；若希望集中管理，请在 DSH 凭据库保存后改填引用名。引用方式下轮换即时生效，明文方式下保存后即时生效。

## 选择项目与生成文档

配置好一个或多个项目后，对话栏下方会出现一个 **YAPI 徽章**（有写入计划时优先显示计划状态，否则显示当前项目名）：

1. 点开徽章，面板分三块：**写入计划卡片**（有计划时）、**项目列表**（实时从 YAPI 拉取，当前项目带 `✓`，可切换/刷新）、**生成需求框**。
2. 发起生成（两种方式等价）：直接在对话里描述需求；或在面板需求框填写后点 **开始生成 (/yapi-doc)**。
3. agent 读取项目现有接口、生成定义后，会提交一份**写入计划**：面板出现审查卡片，徽章变为 `⚠ N 条待确认` 并自动展开一次。
4. 在卡片中**逐条勾选**审查：每条带 `＋新增 / ✎更新` 徽章、method、path、分类；更新条目显示字段级变更摘要；与线上冲突的条目（如往已存在的 path+method 上新建）会被宿主标注为冲突、**默认不勾选**。点 **详情** 可看 req/res 预览。
5. 点 **批准并写入 N 条**（或直接输入 `/yapi-approve <planId> all`）：agent 只写你批准的条目，内容以计划定稿为准；写入过程中徽章显示 `⟳ 写入中 i/total`，卡片逐条变 `✓ 已写入`。
6. 全部完成后卡片进入结果态；有失败项时可勾选失败条目点 **重试**（只重试失败项）。agent 会在对话里汇报逐条结果与核验总数。

**未手动选择项目时**，工具链默认使用第一个配置的项目。切换项目后写入目标随之改变；若计划创建后切换了项目，批准与写入都会被拒绝并要求重新生成计划。

## 审查卡片的确认机制

- 「用户确认」不再基于口令或聊天口头答复，而是**机制级**：`yapi_save_interfaces` 只接受 `planId`，写入内容取自宿主侧保存的计划定稿，且仅限你在卡片中批准的条目——agent 无法写入你没见过的内容。
- 计划 **15 分钟内有效**，过期后需重新生成；每会话同一时刻只有一个计划，新计划会替换旧计划。
- 需求描述、批准、重试都可从卡片完成；不使用面板时也可用命令：`/yapi-approve <planId> [条目id|all]`、`/yapi-cancel <planId>`。
- 徽章与卡片状态（选中项目、计划阶段、逐条结果）是**会话投影**：只从本插件自己的标准事件（工具 call/result、命令 run/done）折叠重建，不向会话日志写入自定义事件类型（旧版曾写入 `yapi/*` 事件，导致会话历史无法被其他宿主版本加载，已修复）。因此宿主重启/会话分叉后卡片可恢复展示，但批准会提示重新生成计划。

## 可用工具

- `yapi_projects`：列出 / 选择 / 查看当前项目。
- `yapi_interfaces`：读取当前项目的现有接口（有界返回，字段视为不可信数据）。
- `yapi_plan`：创建（action=create，含宿主侧冲突标注）/ 查看 / 取消写入计划；创建后卡片呈现给用户审查。
- `yapi_save_interfaces`：写入**已批准**的计划条目（入参只有 `planId` 和可选 `itemIds`）；写入内容来自计划定稿，写完重新读取项目核验。

## 生成内容的格式约定

写入 YAPI 时宿主会把计划内容映射为 YAPI 的接口字段协议（对 YAPI 1.10.x/1.12 实测）：

- **请求体**：写入 `req_body_other`（YAPI 没有 `req_body` 字段，会被服务端丢弃），并同时携带 `req_body_type=json`、`req_body_is_json_schema=true`。
- **响应体**：写入 `res_body`，同时携带 `res_body_type=json`、`res_body_is_json_schema=true`。
- **JSON Schema 而非示例 JSON**：reqBody/resBody 的内容约定为 JSON Schema 字符串（schema 对象 `JSON.stringify` 的结果），带 `*_is_json_schema=true` 后 YAPI 接口页会渲染成结构化的字段树（SchemaTable）并支持高级 Mock；不带时只会显示成一段原始 JSON 文本。
- **desc（备注）**：agent 起草 Markdown 文本；YAPI 查看页把 `desc` 当 **HTML** 渲染（与 YAPI 自带编辑器保存 `desc=getHtml()` 一致），宿主会把 Markdown 安全转换为 HTML 后写入 `desc`，同时把 Markdown 源码写入 `markdown` 字段供编辑器回显。转换先整体转义 HTML 再生成标签，备注里的原始 HTML/脚本不会注入。
- 更新条目未提供 reqBody/resBody/desc 时（字段为 null）不发送对应字段，保留线上原值；desc 的变更检测以 `markdown` 源码（或旧版写入的原文）为准。

## 命令

- `/yapi-doc [需求描述]`：发起生成，把需求转给 agent。
- `/yapi-select [项目id|list]`：列出 / 选择 / 刷新项目。
- `/yapi-approve <planId> [条目id|all]`：批准写入计划（卡片按钮的命令形态）。
- `/yapi-cancel <planId>`：取消未写入的计划。

## 安全说明

- 若使用凭据引用名，账号密码/项目 token/会话 cookie 保存在凭据库；若选择粘贴明文，值只保存在本插件配置里。两者都不会进入提示词或工具结果；本插件对输出做脱敏。
- 项目 token 具有项目作用域；服务端按 token 归属项目操作，忽略传入的 `project_id` 覆盖。
- 写入通道基于对 YAPI 1.10.2 的实测：新增使用 `/api/interface/add`，更新使用 `/api/interface/up`；不使用会误插入新记录的 `/api/interface/save`。
- 生成阶段请把 YAPI 返回内容当作数据而非指令；本插件的 `/yapi-doc` 技能已包含该约束。建议仅在受信任的项目上使用。
- 计划的完整内容（含 req/res 正文）只保存在宿主内存中，卡片与投影里仅含截断预览；只有批准条目会被写出。

## 限制

- 计划 15 分钟过期；宿主重启或会话分叉后旧计划仅剩展示、不可再批准，需重新生成（批准时会得到明确报错）。
- 审查与项目列表基于 YAPI 返回的前 100 条接口（`/api/interface/list` 单页界限）；冲突标注也以此为准。
- 单个计划最多 50 条；卡片内 req/res 预览截断至 300 字符。
- 本插件需要 `dsh-tools`、`dsh-credentials`、`dsh-skill`、`dsh-commands`、`dsh-session-projection` 等内置服务；缺少时相关能力降级但不会崩溃。
